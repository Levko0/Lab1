# Рішення: monorepo

Backend, frontend, конфігурація бази, інфраструктура (CloudFormation) і CI
живуть в одному репозиторії.

1. Атомарні зміни: один коміт змінює API і клієнт, який його викликає,
   тому вони не розходяться.
2. Репозиторій як контекстне вікно агента: ендпоінт, модель, міграцію
   і компонент агент читає за один прохід, а не вгадує контракт між
   окремими репозиторіями.

Компроміс: межа між репозиторіями дає незалежність, але коштує контексту.
Для команди з чотирьох людей і продукту, якого ще немає, контекст важливіший.
